Tableau de bord
  Message d'accueil personnalisé ............ FONCTIONNEL
    → Utilise le prénom saisi dans le Profil. Sans prénom, un lien invite à en
      ajouter un. Le message varie selon l'heure.

  Nombre de candidatures en cours ............ FONCTIONNEL
    → Filtré sur les six statuts actifs. Valeur calculée, jamais fixe.

  Nombre d'entretiens prévus ................. FONCTIONNEL
    → Statuts « Entretien » et « Deuxième entretien » uniquement.

  Nombre de réponses reçues .................. FONCTIONNEL
    → Statuts entretien, deuxième entretien, offre, refusée.

  Prochaines échéances (3 premières) ......... FONCTIONNEL
  Candidatures récemment ajoutées (3) ........ FONCTIONNEL
  Progression générale ....................... FONCTIONNEL
    → Part des candidatures ayant reçu une réponse, avec valeur accessible.

  Encouragement discret ...................... FONCTIONNEL
  Raccourcis vers les actions principales .... FONCTIONNEL

  Ajouter .................................... FONCTIONNEL
  Modifier ................................... FONCTIONNEL
  Consulter le détail ........................ FONCTIONNEL
  Supprimer avec confirmation ................ FONCTIONNEL
    → Modale nommant l'élément. Aucune suppression directe.
    → Les documents rattachés sont détachés, jamais supprimés en silence.

  Rechercher (entreprise, poste, lieu) ....... FONCTIONNEL
  Filtrer par statut ......................... FONCTIONNEL
  Trier par date ou échéance ................. FONCTIONNEL
    → Quatre ordres. Les candidatures sans échéance passent en dernier.

  Les neuf statuts ........................... FONCTIONNEL
    → À préparer, À envoyer, Envoyée, En attente, Entretien, Deuxième
      entretien, Offre reçue, Refusée, Clôturée.

Persistance locale (localStorage) ........... FONCTIONNEL

  Versionnage ................................ version: 1

  Échec d'écriture ........................... détecté et annoncé par un
                                               bandeau rouge en tête d'écran

  ⚠️ LIMITES À CONNAÎTRE
    - Ce n'est pas une sauvegarde cloud. Rien n'est envoyé sur Internet.
    - Vider les données de site de Safari efface tout.
    - Navigation privée : rien n'est conservé.
    - Changer de navigateur ou de téléphone ne transfère rien.
    - iOS peut purger le stockage d'un site peu visité.
    - La plupart des navigateurs plafonnent autour de 5 Mo par origine.

# C. BACKEND SUPABASE — PRÉPARÉ, NON CONNECTÉ
# ---------------------------------------------------------------------------

Réalité actuelle :
  src/supabase.js crée un client si les variables d'environnement sont
  renseignées. AUCUN écran n'appelle ce client. L'application écrit toujours
  dans localStorage. Rien ne part vers Supabase. Rien n'en revient.

  Conséquence : même avec un .env correctement rempli, le Profil affiche
  « Dernière synchronisation : Jamais ». C'est la vérité.

Table profiles .............................. PRÉPARÉE, NON CONNECTÉE
Table applications .......................... PRÉPARÉE, NON CONNECTÉE
Table documents ............................. PRÉPARÉE, NON CONNECTÉE
Table deadlines ............................. PRÉPARÉE, NON CONNECTÉE

Authentification par e-mail ................. PRÉPARÉE, NON CONNECTÉE
Bucket privé « documents » .................. PRÉPARÉ, NON UTILISÉ
  → public = false, quatre politiques.
  → Convention de chemin : <user_id>/<nom-de-fichier>.

Politiques RLS .............................. PRÊTES À EXÉCUTER
  → 3 politiques sur profiles, 4 sur les trois autres tables.
  → Vérification par jointure dans documents.
  → Deux requêtes de contrôle en fin de schema.sql.

# E. CE QUI RESTE À FAIRE — DANS L'ORDRE
# ---------------------------------------------------------------------------

1. Activer GitHub Pages : Settings → Pages → Source → « GitHub Actions ».
2. Créer le projet Supabase gratuit.
3. Exécuter supabase/schema.sql dans l'éditeur SQL.
4. Vérifier RLS et le bucket avec les requêtes de contrôle.
5. Créer ton compte utilisateur dans Authentication → Users.
6. Brancher l'authentification e-mail.
7. Remplacer les lectures localStorage par des appels aux tables.
8. Implémenter le téléversement réel.
9. Envisager les rappels.
